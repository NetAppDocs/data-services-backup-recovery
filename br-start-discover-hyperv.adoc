= Discover and manage Hyper-V workloads in NetApp Backup and Recovery
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Discover Hyper-V virtual machines in NetApp Backup and Recovery so you can protect them with protection policies.

*Required NetApp Console role*
Backup and Recovery super admin. Learn about link:reference-roles.html[Backup and Recovery roles and privileges]. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].

== Add a Hyper-V host and discover resources

Add Hyper-V host information to enable NetApp Backup and Recovery to discover virtual machines. Within each Console agent, select the systems where you want to discover resources.

NOTE: After adding a storage system to NetApp Console, wait a few minutes before discovering resources. Discovering resources immediately after adding a storage system can cause the discovery to fail.

NOTE: When you add Hyper-V hosts and discover resources, NetApp Backup and Recovery installs the NetApp Hyper-V plug-in and the NetApp SnapCenter Windows FileSystem plug-in on the Hyper-V host to help with managing and protecting virtual machines.

.Steps

. From the NetApp Console menu, select *Protection* > *Backup and Recovery*. 
. Select *Discover resources*.
. Enter the following information: 
.. *Workload type*: Select *Hyper-V*.
.. *Hyper-V settings*: Do the following:
... If you haven't yet stored credentials for this Hyper-V host, select *Add credentials*.
+
* Select the Console agent to use with this host.
* Enter a name for this credential.
* Enter the user name and password for the account.
* Select *Done*. 
... Add a new Hyper-V host by entering the host's FQDN or IP address and selecting a Console agent and credentials. If the FQDN is not resolvable by the Console agent, use the IP address instead. For failover clusters, enter the cluster management IP address.
.. *Advanced settings*: Optionally, enter an installation path for the NetApp Hyper-V plug-in. 
. Select *Discover*. 
+
TIP: This process might take a few minutes.

.Result
After NetApp Backup and Recovery discovers resources, the Inventory page displays the Hyper-V workload in the list of workloads.

== Refresh a Hyper-V host

Refresh a Hyper-V host to update the list of VMs on the host and map the connected storage. You might want to do this after a MetroCluster switchover or switchback, or if you have recently added or removed VMs from the host.

IMPORTANT: If a Hyper-V host is protected by a NetApp MetroCluster configuration, refresh the host after every MetroCluster switchover or switchback, and before the next scheduled or manual backup or snapshot. Any backups or snapshots that run for the host before it is refreshed fail. If you don't refresh the host manually, Backup and Recovery refreshes it automatically within 12 hours.

.Steps

. From the NetApp Console menu, select *Protection* > *Backup and Recovery*.
. Select the Hyper-V workload tile.
. From the NetApp Backup and Recovery menu, select *Inventory*. 
. Select the *View* link for the Hyper-V workload type.
. Choose a Hyper-V host to refresh, and select the Actions icon image:../media/icon-action.png[Actions option] > *Refresh*.

== Continue to the NetApp Backup and Recovery Dashboard

.Steps

. From the NetApp Console menu, select *Protection* > *Backup and Recovery*.
. Select the Hyper-V workload tile.
. From the Backup and Recovery menu, select *Dashboard*.
. Review the health of data protection. The number of at risk or protected workloads increases based on the newly discovered, protected, and backed up workloads.
