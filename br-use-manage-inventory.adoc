= Manage Microsoft SQL Server inventory with NetApp Backup and Recovery
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
View and manage Microsoft SQL Server hosts, instances, and databases, and change or remove their protection settings.

You can do the following to manage your inventory: 

* Manage host information
** Suspend schedules
** Edit or delete hosts

* Manage instance information 
** Associate credentials with a resource
** Back up now by starting an on-demand backup
** Edit protection settings

* Manage database information
** Protect databases
** Restore databases
** Edit protection settings
** Back up now by starting an on-demand backup  

* Configure the log directory from *Inventory* > *Hosts* before you back up database host logs in snapshots. For details, see link:br-start-setup.html[Configure NetApp Backup and Recovery settings].



== Manage host information 

Manage host information to ensure that the right hosts are protected. View, edit, and delete host information as needed.

*Required NetApp Console role*
Backup and Recovery super admin, Backup and Recovery backup admin, Backup and Recovery restore admin, or Backup and Recovery clone admin role. If you are protecting data stored on a Cloud Volumes ONTAP cluster, the Cloud Volumes ONTAP Admin role is also required. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].


* Configure log directory. For details, see link:br-start-setup.html[Configure NetApp Backup and Recovery settings]. 
* Suspend schedules 
* Edit a host
* Delete a host 

=== Manage hosts 

You can manage the hosts that are discovered in your system, individually or as a group. 

TIP: To manage a host, look for an "Unmanaged" status in the Hosts column. NetApp Backup and Recovery already manages hosts with a "Managed" status.

After you manage the hosts in NetApp Backup and Recovery, SnapCenter no longer manages the resources on those hosts. 

*Required NetApp Console role*
Backup and Recovery super admin or Backup and Recovery backup admin. If you are protecting data stored on a Cloud Volumes ONTAP cluster, the Cloud Volumes ONTAP Admin role is also required. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].

.Steps
. From the menu, select *Inventory*.
. Select a workload to view the protection details.
. Select the Actions icon image:../media/icon-action.png[Actions option] > *View details*.
. Select the *Hosts* tab.
. Select one or more hosts. If you select multiple hosts, a *Bulk actions* option appears. Select *Manage (up to 5 hosts)*. 

. Select the Actions icon image:../media/icon-action.png[Actions option] > *Manage*.

. Review the host dependencies:
** If the vCenter does not display, select the pencil icon to add or edit the vCenter details.  
** If you add a vCenter, you must also register the vCenter by selecting *Register vCenter*.

. Select *Validate settings* to test your settings.

. Select *Manage* to manage the host.

=== Suspend schedules 

Suspend schedules to stop backup and restore operations during host maintenance.

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the host on which you want to suspend schedules.
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Suspend schedules*.
. In the confirmation dialog box, select *Suspend*.


=== Edit a host

You can change the vCenter server information, host registration credentials, and advanced settings. 

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.

. Select the host that you want to edit.
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Edit host*.

. Edit the host information.
. Select *Done*. 

=== Delete a host

You can delete the host information to stop service charges.

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the host that you want to delete.
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Delete host*.
. Review the confirmation information and select *Delete*.

== Manage instance information 

Manage instance information to protect resources, associate or remove credentials, edit protection settings, and run backups:

* Protect instances
* Associate credentials
* Disassociate credentials
* Edit protection settings 
* Back up now   

*Required NetApp Console role*
Backup and Recovery super admin or Backup and Recovery backup admin role. If you are protecting data stored on a Cloud Volumes ONTAP cluster, the Cloud Volumes ONTAP Admin role is also required. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].

=== Protect database instances  

Assign a policy to a database instance to govern the schedule and retention of resource protection.

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the workload that you want to view and select *View*.
. Select the *Instances* tab. 
. Select the instance. 
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Protect*.
. Select a policy or create a new one. 
+
For details about creating a policy, see link:br-use-policies-create.html[Create a policy].

. Provide the scripts to run before and after the backup.

* *Pre-script*: Enter the script filename and location to run automatically before the protect action starts. Use this to perform additional tasks or configurations before the protection workflow.
* *Post-script*: Enter the script filename and location to run automatically after the protection action completes. Use this to perform additional tasks or configurations after the protection workflow.



. Provide verification information for the snapshot:

* Storage location: Select where to store the verification snapshot.
* Verification resource: Select whether to verify the resource on the local snapshot, on ONTAP secondary storage, or both.
* Verification schedule: Select the frequency: hourly, daily, weekly, monthly, or yearly.

=== Associate credentials with a resource 

You can associate credentials with a resource so protection can occur. 

For details, see link:br-start-configure.html[Configure NetApp Backup and Recovery settings, including credentials].

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the workload that you want to view and select *View*.
. Select the *Instances* tab. 
. Select the instance. 
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Associate credentials*.
. Use existing credentials or create new ones. 



=== Edit protection settings

You can change the policy, create a new policy, set a schedule, and set retention settings.

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the workload that you want to view and select *View*.
. Select the *Instances* tab. 
. Select the instance. 
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Edit protection*.
+
For details about creating a policy, see link:br-use-policies-create.html[Create a policy].

=== Back up now 

Back up your data now to protect it immediately.

.Steps
. From the NetApp Backup and Recovery menu, select *Inventory*.
. Select the workload that you want to view and select *View*.
. Select the *Instances* tab. 
. Select the instance. 
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Back up now*.
. Choose the backup type and set the schedule.
+
For details about creating an ad hoc backup, see link:br-use-mssql-backup.html[Back up Microsoft SQL Server workloads].

=== Back up now 

You can back up your Microsoft SQL Server instances and databases now to protect your data immediately.

*Required NetApp Console role*
Backup and Recovery super admin or Backup and Recovery backup admin role. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].


.Steps

. Select the instance or database. 
. Select the *Actions* image:icon-action.png["Actions icon"] icon, and select *Back up now*.
