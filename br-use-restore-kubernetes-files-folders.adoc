= Restore or download Kubernetes files and folders using the NetApp Backup and Recovery web UI
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Restore applications that are protected with a protection policy in NetApp Backup and Recovery. To restore an application, you need at least one restore point, which can include a local snapshot, an object store backup, or both. You can restore from the local, secondary, or object store copy.

== Restore Kubernetes files and folders
You can restore namespace-based or VM-based applications from a restore point, either by restoring all resources or by selecting a subset of resources to restore.

.Before you begin
If you are restoring an application that was backed up using Trident Protect, ensure that Trident Protect is installed on both the source and destination clusters.

*Required NetApp Console role*

Backup and Recovery super admin or Backup and Recovery restore admin. link:reference-roles.html[Learn about NetApp Backup and Recovery access roles]. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].

.Steps

. In the NetApp Backup and Recovery menu, select *Restore*.
. Choose a Kubernetes application from the list, and select *View and Restore* for that application.
+
The list of restore points appears.
. Select the *Actions* image:icon-action.png["Actions icon"] icon for a restore point, and open the *Restore files and folders* menu.
. Select the source location to restore from (snapshot, secondary, or backup).
. Select a virtual machine from the recovery point to browse its files and folders.
. Select *Next*.
+
The file browser appears.
. Browse the list of files and folders, and select files and folders to restore.
+
Open a partition to browse its files and folders. When you select a file or folder to restore by enabling its checkbox, it is added to the "selected" list to the right.
. When finished, select *Next*.
. Select the *Transfer to VM* transfer mode.
. Choose destination settings:
+
* *Restore to original VM*: Enable this option to restore to the original virtual machine.
** *Restore to the same path as in the backup*: Enable this option to restore to the same path used in the backup.
** *Alternate path*: To restore to a different path, enable this option and enter the preferred path.
* *Restore to alternate VM*: Enable this option to restore to a different virtual machine in the cluster. Select a VM from the list, and enter a destination path for the restored files or folders.


. In the *Guest virtual machine credentials* section, select the credentials for the guest VM.
+
If you haven't yet stored credentials for this guest VM, select *Add credentials* to link:br-start-configure.html#add-credentials-for-host-resources[add a new credential] for the guest VM.
. Review and confirm the file or folder restore settings.
. Select *Restore*.

== Download Kubernetes files and folders
You can download namespace-based or VM-based applications from a restore point, either by restoring all resources or by selecting a subset of resources to restore.
