= Clone Oracle Database workloads with NetApp Backup and Recovery
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Use NetApp Backup and Recovery to create writable clones of Oracle Database workloads from on-premises ONTAP systems on primary or secondary storage. You can also schedule clone refreshes to meet your requirements.

*Required Console role*
Backup and Recovery super admin or Backup and Recovery clone admin role. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html[Learn about NetApp Console access roles for all services^].

== Create a clone of an Oracle database

Create a clone immediately from an existing snapshot. Use this method to create a one-time clone that is not continuously refreshed from a snapshot.

.Steps 

. From the NetApp Console menu, select *Protection > Backup and Recovery*.
. Under *Workloads*, select the *Oracle* tile.
. Select *Clone*. 
. Select *Create new clone*.
. In the *Database source* section, choose the source host and database from the lists.
.. If the source database is a container database (CDB), in the *Clone type* section select one of the following:
+
* *Complete database clone*: Clones the entire container database, including all PDBs.
* *PDB clone*: Clones a specific PDB from the container database backup into an existing target container database.
. In the *Database target* section, choose the target host and database from the lists. The destination host and database can be different from the source. 
. Select *Next*.
. In the *Clone from* section on the *Select restore point* page, select *Existing snapshots*.
. Choose an existing snapshot (restore point) from the list to use as a base for the clone and select *Next*.
+
The *Select snapshot location* page appears if the snapshot is stored in more than one location.
. Choose the snapshot location to use and select *Next*.
. On the *Advanced options* page, do the following:
.. Optionally, if you are cloning a complete database, in *Complete database clone settings*, select one or more PDBs to exclude from the clone (PDB$SEED is always excluded).
.. If you have previously saved a specification file, you can upload it to customize the cloned database settings. You can also download the default specification file for the database snapshot.
.. In the *Recovery scope* section, choose how to limit what is restored to create the clone and enter the required information for the option you choose. Choosing *None* restores all data.
.. In the *Prescripts and postscripts* section, enable one or both of the *Prescript* and *Postscript* options to execute a script before the clone operation begins or after it completes. For each option, enter the full script path and any required arguments. 
. Select *Clone*.

== Schedule a clone of an Oracle database

Create an instant clone and schedule regular refreshes to keep it current with the latest database state.

NOTE: Creating an instant snapshot and clone with a refresh schedule applies to complete database clones only. It is not available for a PDB clone. 

.Steps 

. From the NetApp Console menu, select *Protection > Backup and Recovery*.
. Under *Workloads*, select the *Oracle* tile.
. Select *Clone*. 
. Select *Create new clone*.
. In the *Database source* section, choose the source host and database from the lists.
. In the *Database target* section, choose the target host and database from the lists. The destination host and database can be different from the source.
. Select *Next*.
. In the *Clone from* section on the *Select restore point* page, select *Instant snapshot and clone*.
. Choose a location to store the snapshot when it is created.
. Select *Next*.
. On the *Advanced options* page, do the following:
.. To customize the cloned database settings, enable the *Customize target database parameters* option. If you have previously saved a specification file, this option enables you to upload it to customize the cloned database settings. You can also download the default specification file for the database that reflects its current settings.
.. In the *Clone refresh schedule* section, choose when and how often to refresh the clone. The refresh updates the instant snapshot and overwrites the existing clone with a new copy.
.. In the *Prescripts and postscripts* section, enable one or both of the *Prescript* and *Postscript* options to execute a script before the clone operation begins or after it completes. For each option, enter the full script path and any required arguments. 
. Select *Clone*.

== Clone a pluggable database (PDB) 

Clone a single PDB from a container database (CDB) backup into an existing target CDB. Use this method when you need only one pluggable database for development, testing, or analytics, instead of cloning the entire container database. 

.Before you begin

* The source database must be a container database (CDB). 
* The target host must already have a running container database. 
* Instant snapshot and clone (scheduled refresh) is not supported for a PDB clone. Use an existing snapshot. 
* Recovery is required for a PDB clone; you cannot skip recovery. 

.Steps 

. From the NetApp Console menu, select *Protection > Backup and Recovery*.
. Under Workloads, select the *Oracle* tile.
. Select *Clone*.
. Select *Create new clone*.
. In the *Database source* section, choose the source host and the source container database from the lists.
. In the *Database target* section, choose the target host. The target host must already have a running container database. A target database name is not required because the PDB is cloned into an existing container database.
. In the *Clone type* section, select *PDB clone*.
. Select *Next*.
. In the *Clone from* section on the *Select restore point* page, select *Existing snapshots*. Instant snapshot and clone is not available for a PDB clone.
. Choose an existing snapshot from the list and select *Next*.
. If the snapshot is stored in more than one location, the *Select snapshot location* page appears. Choose the snapshot location and select *Next*.
. On the *Advanced options* page, in the *PDB clone settings* section, do the following:
.. In the *Pluggable database* list, select the PDB to clone.
.. In the Target container database list, select the container database where the cloned PDB is created.
.. In *PDB clone name*, enter a name, or select *Suffix* to append text to the source PDB name. The name can contain alphanumeric characters and underscores, must start with a letter, and can be up to 64 characters. When cloning into the same container database as the source, the clone name must differ from the source PDB name.
.. Enable *Open PDB after clone* to open the cloned PDB in READ-WRITE mode when the clone completes. This option is enabled by default.
. In the *Recovery scope* section, select a scope to which the recovery should be limited, and enter the required information. Recovery scope is required for a PDB clone.
. In the *Prescripts and postscripts* section, optionally enable the *Prescript* and *Postscript* options and enter the script path, any arguments needed, and a script timeout in seconds.
. Select *Clone*.

== Split a clone

You can split a clone of your Oracle Database workloads to create an independent or long-term copy. Splitting a clone creates a new backup from the clone that can be used for protection and restore operations.

The split operation displays the aggregates that are part of the storage VM, their sizes, and where the cloned volume resides. NetApp Backup and Recovery indicates whether sufficient space is available to complete the split. After the split, the clone becomes independent. The original clone job remains available for future operations.

.Steps
. From the NetApp Backup and Recovery menu, select *Clone*.
. Select a clone.
. Select the Actions icon image:../media/icon-action.png[Actions option] > *Split clone*.
. Review the split clone details and select *Split*.
. When the split clone is created, you can view it in the *Inventory* page.

== Delete a clone

Remove clones of your Oracle Database workloads to free up storage space. If a policy protects the clone, both the clone and its associated job are deleted.

.Steps

. From the NetApp Backup and Recovery menu, select *Clone*.
. Select a clone.
. Select the Actions icon image:../media/icon-action.png[Actions option] > *Delete clone*.
. In the Delete clone confirmation dialog box, review the deletion details.
.. To delete the cloned resources from SnapCenter even if the clones or their storage is not accessible, select *Force delete*. 
.. Select *Delete*.
. When the clone is deleted, it is removed from the *Inventory* page.
